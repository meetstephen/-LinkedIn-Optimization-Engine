# Voice system rebuild: fewer tokens, more humanity

The post generation system has been rewritten around a single thesis: show the model what good looks like instead of explaining it in 600 words of rules. The HUMAN_VOICE_PRIMER drops from ~600 words to 189, a new `core/examples.py` module injects 2 randomly-selected few-shot examples into every prompt, the generator now produces one post instead of two, and Nigerian professional warmth ("we" framing, directness about money, flowing paragraph rhythm) is baked into the core voice rather than bolted on as an industry-specific addon. The polish pass and industry profiles are updated to match the loosened structural rules (questions allowed, no-CTA allowed, varied paragraph lengths).

**Watch for:** `image_generator.py` line 145 still reads `st.session_state.get("pg_var1")` — this key no longer exists, so the image generator's pipeline pre-fill from Post Generator is broken (confirmed). The `---NOTE---` delimiter parsing is more fragile than the old `---VARIATION 1---` regex since any stray dashes in the model's output could trigger a false split (likely). The few-shot examples are sampled randomly without a seed, meaning identical inputs produce non-deterministic prompts — fine for production but makes debugging or A/B comparison impossible (confirmed).

## High-level view

The voice primer is now a creative brief rather than a compliance checklist. Three governing principles plus a handful of concrete mechanical rules replace two pages of "drop X, never Y" instructions. The old per-phrase "drop" rules were already present in BANNED; the primer just sets tone now.

Few-shot examples carry the instruction load that the old verbose primer tried to achieve through description. Six hand-written Nigerian-professional posts demonstrate the target quality calibre directly. Two are sampled per prompt via `random.sample` with no seed, injected between the primer and task instructions.

The generator's output contract changed from a multi-variation format (two posts + analysis) to a single post followed by an optional `---NOTE---` line describing the angle used. Session state keys changed from indexed (`pg_var1`, `pg_var2`) to singular (`pg_post`, `pg_note`). At least one other module (`image_generator.py`) still reads the old key, so the cross-module pipeline is broken.

The polish pass and structure rules now allow hooks that are questions, paragraphs that flow past one idea, and posts that end without a CTA — matching the stylistic variety the few-shot examples demonstrate.

## Broken cross-module session state contract

The diff renames session state keys but doesn't update consumers outside `post_generator.py`. Confirmed breakage:

```python
# image_generator.py line 145
_piped_content = (
    st.session_state.get("pg_var1")        # ← key no longer set
    or st.session_state.get("last_generated_post", "")
)
```

The `or` fallback means the image generator won't crash — it falls through to `last_generated_post`. But `last_generated_post` is set to the raw streamed `result` which includes the `---NOTE---` delimiter and the angle description line. So the image generator will receive post content plus metadata text, slightly polluting the image prompt. The fix is to read `pg_post` (the clean extracted post) instead of `pg_var1`.

## Output delimiter fragility

The old delimiters (`---VARIATION 1---`) were distinctive enough that a model would never produce them inside post content. The new `---NOTE---` is parsed by:

```python
_note_match = _re.search(r"-+\s*NOTE\s*-+", result, _re.DOTALL | _re.IGNORECASE)
```

This matches case-insensitively and allows variable dash counts. A post containing "--- A note on methodology ---" would trigger a false split, truncating the visible post at that point. The risk is low for typical LinkedIn content but exists for posts about documentation workflows, engineering processes, or meeting culture.

## Non-deterministic example selection

`build_post_prompt()` calls `get_examples(2)` on every invocation with no seed. The generation signature (`_generation_signature`) already exists and produces a stable hash for temperature escalation — it could trivially seed `random.seed()` before sampling so that the same (topic, niche, tone, framework) tuple always sees the same two examples. Without this, debugging "why did the model produce X?" requires also knowing which examples it saw, and the only record is the stashed prompt debug expander (which most users won't check).
