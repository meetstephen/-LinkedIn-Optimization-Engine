# Voice system coherence overhaul and engagement prediction

The change aligns all six content-generation modules (post_optimizer, repurposing_engine, engagement_toolkit, content_ideas, engagement_intelligence, app.py inline prompts) with the canonical voice system in `core/voice.py`. Stale prompt rules — hard 12-15 word hook limits, blanket "no questions" bans, rigid "one idea per line" formatting — are replaced with the updated STRUCTURE_RULES that allow 25-word hooks, specific questions, and varied paragraph lengths. Few-shot examples from `core/examples.py` are injected into four modules for quality calibration. A second feature adds a deterministic engagement prediction score and a Schedule pipeline button to `post_generator.py`.

**Watch for:** The Schedule button sets `scheduler_pipe_content` in session state but the Content Scheduler never reads it — the pipe is dead on arrival (confirmed). Two new helper functions (`get_hook_examples`, `get_comment_examples`) are defined and tested but never called from any production module (confirmed). The `_predict_engagement` function has no test coverage despite being the most logic-dense addition (confirmed).

## High-level view

The prompt alignment is consistent: every module that previously hard-coded hook word limits or banned questions now uses phrasing that mirrors `core/voice.py`'s STRUCTURE_RULES. The few-shot injection pattern is uniform — deterministic seed from the input text's first 50 chars, `get_examples(2)` for post-like modules and `get_examples(1)` for comments — except `engagement_intelligence.py` and `engagement_toolkit.py` which use unseeded calls, meaning their prompts vary across reruns for the same input.

The engagement prediction scorer is a 100-line deterministic function that scores posts on five axes (hook, length, specificity, structure, emotional pull) using regex and keyword matching. The hardcoded Nigerian place names and specific self-interruption phrases in the scoring logic create a geo/style coupling that will need updating if the product expands beyond its current Nigerian professional audience.

The Schedule pipeline button follows the established `_pending_nav` + `st.rerun()` pattern used by the other five buttons, but the receiving module (`render_content_scheduler` in app.py) has no code to consume the piped content.

## Dead-end Schedule pipeline button

The Schedule button in `post_generator.py` (line 943-949) follows the same pattern as the working Optimize, Hook, Visual, and Save buttons:

```python
st.session_state["scheduler_pipe_content"] = post_content
st.session_state["_pending_nav"] = "📅 Content Scheduler"
st.rerun()
```

The `_pending_nav` mechanism works — app.py's cross-module navigation handler (line 3587) pops the key and sets `current_page`, so the user does land on the Scheduler page. But `render_content_scheduler()` (line 2928 onward) never checks for `scheduler_pipe_content`. Compare with the Post Optimizer, which explicitly pops `po_content_pipe` at line 129 and pre-fills the text area. The Scheduler has no equivalent. The session key accumulates silently in `st.session_state`.

## Unused helpers: get_hook_examples and get_comment_examples

`core/examples.py` now exports three public functions: `get_examples()` (existing, used by 4 modules), `get_hook_examples()` (new, used by 0 modules), and `get_comment_examples()` (new, used by 0 modules). The FEAT-002 spec mentions using hook examples in `engagement_toolkit.py` for quality calibration, but the implementation uses `get_examples(2)` (full post examples) instead. The hook-specific examples — short, first-line calibrators — are better suited for a hook-generation module than full 300-word posts. Similarly, `engagement_intelligence.py` uses `get_examples(1)` rather than `get_comment_examples()`, which contains purpose-built 2-4 sentence examples at the exact length and style a comment should target.

## Engagement prediction scoring logic

`_predict_engagement()` decomposes a post into five 0-20 subscores that sum to 0-100:

```
Hook Strength:  baseline 10 + word-count bonus + not-I bonus + numbers + dialogue
Length:         band scoring (sweet spot 150-500 words = 18)
Specificity:    numbers count + dialogue + time words + Nigerian places
Structure:      paragraph count + length variance + blank-line presence
Emotional Pull: vulnerability keywords + contrast words + specific phrases
```

The "Emotional Pull" factor checks for exact string matches: `"And honestly?"`, `"Here's the thing."`, `"I mean that literally."` These are the three self-interruption phrases from `HUMAN_SIGNATURES`, but that section presents them as examples of a pattern, not an exhaustive list. A post using a different self-interruption (`"Wait. Let me back up."`) gets zero credit for that signal. The scoring function effectively rewards posts that parrot the example phrases rather than posts that exhibit the underlying quality.

The specificity bonus for Nigerian place names (`+2`) creates a silent scoring penalty for users writing about other geographies — posts about Lagos look more "specific" than posts about Nairobi even if both name a real place.
